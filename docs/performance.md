# Performance Review

Approach: keep the marketing surface fast and crawlable by default, and lean on Next.js primitives (static rendering, `next/font`, `next/image`) instead of custom optimization. Trade-offs on client-side rendering, bundle size, and third-party scripts are documented explicitly where they exist.

## Core Web Vitals — targets and current expectation

| Metric | Target (mobile 4G) | Expected on this codebase | Confidence |
|---|---|---|---|
| LCP | ≤ 2.5s | Landing: **2.0–2.5s** — the hero image (real product screenshot, `priority`) is the LCP element. Signup / welcome: ~1.0s (text-first, no LCP image). | Medium |
| INP | ≤ 200ms | Well under target — no heavy synchronous work; the sticky CTA IntersectionObserver and the feature carousel scroll handler are the only client interactions and both are passive. | High |
| CLS | ≤ 0.1 | Near-zero — every image has explicit `width`/`height` or a fixed `aspect-*` container; fonts loaded via `next/font` with `display: swap` and no layout shift on swap. | High |

Numbers pending live Lighthouse run on the deployed URL.

## Performance decisions

### Rendering strategy

- **Static rendering by default** — `/`, `/signup`, `/welcome` are all pre-rendered (`○` in the `next build` output).
- **API routes are dynamic** (`ƒ`) — expected, they read env + call Notion.
- **`/opengraph-image`** runs on the `edge` runtime for lower latency on social crawlers.
- **Known deviation:** `app/page.tsx` is currently `'use client'` because the A/B variant is resolved via PostHog's JS SDK on mount. This forces the landing tree to hydrate. Documented in [trade-offs.md](./trade-offs.md) with the fix path (server-side flag resolution via cookie bootstrap).

### Loading strategy

- **`next/image`** for every raster asset. Automatic WebP/AVIF conversion, responsive `sizes`, lazy loading by default.
- **`priority`** set only on the hero image (`Hero.tsx`) — the LCP element on the landing above the fold.
- **`unoptimized`** on SVGs — Next.js does not process SVGs through its image optimizer (security default). The SVG feature screenshots are already vector; no optimization needed.
- **`next/font/google`** for Lato and Nunito Sans — self-hosted, no external font requests at runtime, `display: swap` to prevent FOIT.

### Asset optimization

- **Product screenshots** — pulled as SVG from fxreplay.com's CDN and self-hosted under `public/product-features/`. SVG scales without generation cost.
- **Testimonial avatars** — self-hosted PNGs, served with automatic `next/image` optimization (browser gets WebP if supported).
- **OG image** — dynamically generated by `app/opengraph-image.tsx` (`next/og` Satori) at 1200×630 PNG. Cached by Vercel's edge network after first request.
- **Favicon** — SVG isotype from the brand kit, served from `app/icon.svg`.

### JavaScript execution

- Client component boundaries kept narrow — most sections (`HowItWorks`, `Features`, `FreeTier`, `SocialProof`, `Footer`) are server components with no JS shipped.
- Client components are leaves — `PageviewTracker` (empty render + `useEffect`), `CtaLink` (link + `onClick`), `StickyCTA` (IntersectionObserver), `AnimatedNumber` (rAF + IO), `SignupForm` (form state).
- **PostHog SDK** loads client-side in `PostHogProvider.tsx` via `useEffect` — deferred past hydration. Internal queueing handles events fired before init.

### Third-party scripts

Only PostHog. Loaded via the `posthog-js` npm package, initialized inside a `useEffect` (never blocking). No Google Analytics, GTM, chat widgets, or heatmap libraries.

Trade-off: PostHog SDK adds ~90kB gzipped to the First Load JS. Documented in [trade-offs.md](./trade-offs.md) with the fix path (`next/dynamic` for the provider so it loads after LCP).

## SEO

### Metadata

- **Per-route `metadata` exports** — `app/layout.tsx` (site-level defaults), `app/signup/page.tsx` and `app/welcome/page.tsx` (route-specific + `robots: noindex`).
- **`metadataBase`** set from `NEXT_PUBLIC_SITE_URL` — resolves `openGraph.images` and canonical URLs to the production origin, not localhost.
- **`alternates.canonical`** on `/` — prevents indexing dilution from query params (`?v=variant_a`, `?utm_source=…`).
- **OpenGraph + Twitter card** — auto-generated from `app/opengraph-image.tsx`, plus explicit `openGraph.siteName`, `openGraph.locale`, `twitter.card: 'summary_large_image'`.

### Structured data (JSON-LD)

- **`Organization`** — in `app/layout.tsx`, sitewide.
- **`WebSite`** — in `app/layout.tsx`, sitewide.
- **`FAQPage`** — in `components/landing/FAQ.tsx`, colocated with the visible FAQ so the two never drift. Google-eligible for FAQ rich results in SERP.

### Sitemap and robots

- `app/sitemap.ts` — generates `sitemap.xml` at build time listing `/` (the only indexable route).
- `app/robots.ts` — generates `robots.txt` allowing `/`, disallowing `/signup`, `/welcome`, `/api`.

### Semantic structure

- One `<h1>` per page.
- Landmarks: `<header>`, `<main>`, `<nav>`, `<footer>`, `<section>`.
- `<html lang="en">` set in the root layout.

## Accessibility

Reviewed by an in-house a11y agent (`.claude/agents/a11y-reviewer.md`) on each surface — landing, signup, welcome — during development.

**Applied:**

- **Skip-to-content link** — visible on focus, target `#main` on every page (each `<main>` has `tabIndex={-1}` for programmatic focus after activation).
- **Focus-visible ring** — global default in `globals.css` — 2px `--focus-ring` blue with offset, respects `prefers-reduced-motion`.
- **Form labels + errors** — every input has an associated `<label>`; error messages linked via `aria-describedby`; async submission state announced via a visually-hidden `role="status" aria-live="polite"` region.
- **Required fields marked in text** — `Email (required)` and `Name (required)` — sighted users are informed without relying on color or asterisk-alone.
- **Semantic HTML** — `<button>` for actions, `<a>` for navigation, native `<details>` for the FAQ (keyboard-nav free), no `<div onClick>`.
- **ARIA labels** on icon-only controls (arrow buttons in the carousel, prev/next in navigation, dropdown togglers).
- **StickyCTA `inert`** when hidden — prevents focus trap on off-screen focusable content.
- **`prefers-reduced-motion`** — global rule in `globals.css` disables all `transition` and `animation` for users with the preference set. `AnimatedNumber` also checks the media query and jumps to the final value.
- **Alt text** — meaningful for content images (avatars: `Portrait of Mack Grey, Trader`; product screenshots: `Feature name — product interface screenshot`); empty for decorative.

**Deferred**  (documented in [trade-offs.md](./trade-offs.md)):

- Full color-contrast audit against WCAG AA on every token combination.
- Focus-restore on API error in the signup form.
- Automated a11y CI (axe-core in Playwright).

## Caching and CDN

- **Vercel Edge Network** by default — static pages served from the closest edge, cached until the next deploy.
- **`Cache-Control`** — Next.js defaults for static assets (`immutable, max-age=31536000` for hashed files; `no-cache` for HTML).
- **Notion writes** are per-request server-side; not cached.
- **PostHog** events go directly from browser to PostHog Cloud; no server involvement.
- **Sitemap and OG image** re-generate per request in the current setup (small cost). In production, would set explicit revalidation windows.

## Important production risks

Ranked by impact if this went to real traffic:

1. **Notion rate limits (3 requests / second per integration).** Any signup spike hits the ceiling. Fix: swap the Notion adapter for Postgres before scaling past ~10k signups/day. See [trade-offs.md](./trade-offs.md).
2. **Client-side flag resolution causes a variant flash.** The landing SSRs with `control` and swaps to `variant_a` on the client if PostHog assigns it. Users on slow networks see a visible content change. Fix: bootstrap the flag server-side from cookies (PostHog supports this natively).
3. **No consent banner for EU traffic** — technically a GDPR gap. Fix: opt-in gate via a lightweight banner + `posthog.opt_out_capturing()` until acceptance.
4. **No rate limiting on `/api/users`** — a scripted signup flood would fill the Notion database (and after migration, the users table). Fix: Vercel middleware with IP-based limit, or Cloudflare WAF upstream.
5. **PostHog SDK failure would drop events silently** — the `track()` wrapper is fire-and-forget. Fix: queue in IndexedDB and retry via a service worker.
6. **Notion outage means signup failures** — the storage adapter throws and the API returns 500. Fix: local write-through cache with an async replay job when Notion recovers.
7. **No Sentry** — client errors ship to the browser console only. Fix: wire `@sentry/nextjs` — production essential.
8. **Bundle size on the landing (~208kB First Load JS)** — dominated by the PostHog SDK. Fix: `next/dynamic` for the provider, defer past LCP.
9. **No CI** — the pre-commit hooks are local; a broken push would deploy. Fix: GitHub Actions with `typecheck + lint + build + Playwright smoke`.
